# Matching Algorithm — Glossário

Termos canônicos do domínio de **distribuição progressiva de pedidos** (matching/dispatch de Service Requests). Sem detalhes de implementação.

**ADRs:** [0001](./adr/0001-replace-open-feed-with-progressive-matching.md) feed progressivo · [0002](./adr/0002-dual-location-model-batch-vs-feed.md) localização · [0003](./adr/0003-list-provider-opportunities-rpc.md) RPC feed · [0004](./adr/0004-dispatch-gates-cron-and-scheduling.md) gates/cron · [0005](./adr/0005-service-ratings-and-provider-stats.md) ratings. Requisitos: [`requirements.md`](./requirements.md).

| Termo | Significado |
|-------|-------------|
| **Matching progressivo** | Modelo de **descoberta** de pedidos via batches + fallback lazy. **Substitui o feed aberto** (`match_provider_jobs`) na **listagem** (#1). Detalhe (`get_service`) e ações (propor/chat) **não** exigem visibilidade de batch (#76–#77). |
| **Service Request Dispatch** | Ciclo de vida operacional de um pedido dentro do matching progressivo (estados como `DISPATCH_ACTIVE`, `DISPATCH_PAUSED`, etc.). **Não** confundir com dispatch do Message Dispatcher. |
| **Batch** | Lote de até **`matching.batch_size`** prestadores (default 10) que recebem visibilidade e notificação de um pedido em um momento do ciclo (#89). |
| **Visibilidade** | Direito de ver/agir sobre um pedido no feed. **Batch:** persistida em `service_request_provider_visibility`. **Fallback:** computada na RPC quando `fallback_opened_at IS NOT NULL` (#75, #85). Cumulativa (batch) até match/cancel; após `EXPIRED`, só batch persistido permanece (#66). |
| **Feed de oportunidades** | Lista **gated** por visibilidade (batch + fallback lazy) via `list_provider_opportunities`. Oculta SR se proposta in-flight, chat **ACTIVE**, ou prestador **já propôs alguma vez** naquele SR (#95, #96). |
| **Detalhe do serviço** | RPC **`get_service`** — qualquer prestador autenticado com `service_request_id`/link (#76); já implementado via `service_viewer_has_access`. |
| **Ações do prestador** | Propor/chat em SR **`OPEN`** sem gate de visibilidade (#77). **`DISPATCH_STOPPED`** bloqueia só **novas propostas** (#78, #88); **novos chats** seguem slots CNS — discovery sem proposta permitido se houver slot (#88). |
| **Localização operacional (batch)** | Posição do prestador lida de `user_device_beacons` para elegibilidade geoespacial em batches, ranking de candidatos e decisão de inclusão/notificação. |
| **Localização de navegação (feed)** | Coordenadas obtidas no momento do acesso à tela de trabalhos (Capacitor / browser), usadas só para enriquecer o feed (ex.: distância, ordenação). **Não** substitui beacon na elegibilidade de batch. |
| **Fallback (marketplace aberto)** | Última fase: pedido exposto a prestadores elegíveis por categoria/serviço e **bairro exato** (`provider_service_area_neighborhoods`) quando batches esgotam sem match. Sem notificações em massa. |
| **Avaliação de serviço** | Feedback **multidimensional** dado **somente pelo cliente** ao prestador após conclusão. Vinculada ao **`contracted_service`** (não ao `service_request`); elegibilidade para avaliar segue **`contracted_services.status`**. |
| **Nota geral da avaliação** | Média **ponderada** das dimensões daquela avaliação individual. |
| **Score de qualidade do prestador** | Agregado das notas gerais ao longo de todos os serviços (média + **volume mínimo** antes de pesar no ranking). Todo prestador **inicia em 5 estrelas**; a nota pode cair conforme recebe avaliações reais. |
| **Detalhe da avaliação (prestador)** | O prestador **vê avaliações individuais** recebidas (dimensões + comentário opcional), além do agregado público no perfil. |
| **Status operacional do prestador** | `profiles.operational_status`: `active` (participa de matching) ou `suspended` (só executa serviços já contratados). Alteração **somente por admin**; mecanismo admin fora do MVP (decisão #52). |
